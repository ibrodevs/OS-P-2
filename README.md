## Инструкция по установке и запуску

### 1. Клонирование

```bash
git clone https://github.com/ibrodevs/OS-P-2.git
cd OS-P-2
```

### 2. Сделать shell-скрипты исполняемыми

```bash
chmod +x report.sh run_analysis.sh
```

### 3. Проверить анализ логов

```bash
./report.sh logs ERROR
./report.sh logs WARN
./report.sh --top 2 logs ERROR
```

### 4. Запустить Python-программу

```bash
python3 hello.py test.txt
```

### 5. Выполнить анализ `strace`

```bash
./run_analysis.sh
```

Или вручную:

```bash
strace -f -o trace.txt python3 hello.py test.txt
strace -f -c -o python_summary.txt python3 hello.py test.txt
strace -f -o cat_trace.txt cat test.txt
strace -f -c -o cat_summary.txt cat test.txt
```

## Выполнение задания

### 1. Анализ журналов через `report.sh`

Скрипт принимает каталог и уровень `ERROR` или `WARN`, затем выводит таблицу вида «модуль → количество сообщений» по убыванию.

Пример:

```bash
./report.sh logs ERROR
```

Для приложенных тестовых логов модули с ошибками располагаются по убыванию количества сообщений.

Если обязательные аргументы не переданы, скрипт печатает справку и завершает работу с кодом `1`.

### 2. Режим `--top N`

Дополнительный параметр ограничивает количество строк результата:

```bash
./report.sh --top 2 logs ERROR
```

Также реализована проверка существования каталога и корректности уровня сообщения.

### 3. Программа `hello.py`

Программа открывает переданный файл, читает его и выводит размер в байтах:

```bash
python3 hello.py test.txt
```

Для приложенного тестового файла выводится его фактический размер.

### 4. Анализ системных вызовов

`strace` показывает, что запуск Python требует не только системных вызовов для непосредственного чтения `test.txt`, но и множества операций, связанных с запуском интерпретатора, загрузкой библиотек, модулей и настройкой памяти.

Фактически получено:

| Программа | Всего системных вызовов |
|---|---:|
| `python3 hello.py test.txt` | **571** |
| `cat test.txt` | **121** |

С самим исследуемым `test.txt` в Python-трассировке напрямую связано **8 системных вызовов**.

### 5. Сравнение `cat` и Python

`cat` — небольшая специализированная системная утилита, поэтому ей требуется значительно меньше подготовительной работы. Python сначала запускает полноценную среду выполнения, загружает необходимые библиотеки и только после этого выполняет пользовательский код.

Поэтому число системных вызовов у Python существенно больше, даже если обе программы выполняют похожую операцию чтения файла.
